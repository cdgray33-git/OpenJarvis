## HARD FACTS A NEW WINDOW WILL GET WRONG
- **AN ACTIVE AUDIO SESSION IS NOT AUDIBLE AUDIO.** ttsPlayer holds a looping
  SILENT keepalive at `KEEPALIVE_GAIN = 0.0` for the life of the
  AudioContext. That alone shows `state=1 vol=1.00 mute=False`. Only a PEAK
  reading distinguishes audio from silence. Claude got this wrong in W64 and
  corrected in-window.
- **THE SPEECH PATH IS NOT ON THE KEEPALIVE GAIN.** `schedule()` connects to
  `masterGain` (gain 1) -> destination; the keepalive has its own separate
  gain node. There is no gain-zero speech path. Do not re-propose it.
- **A DELIVERED .ps1 WILL NOT RUN AS DELIVERED.** Mark-of-the-web plus
  execution policy block it. Every script needs `Unblock-File` AND
  `powershell.exe -ExecutionPolicy Bypass -NoProfile -File <ABSOLUTE path>`,
  given in the SAME message as the file.
- **PASTING A SCRIPT BODY IS NOT RUNNING IT.** A pasted `param()` prompts
  interactively and its defaults never reach the rest of the paste, giving a
  confident empty result (`duration=s`, `samples=0`).
- **TWO api.ts FILES:** `frontend\src\lib\api.ts` (1007 lines;
  `synthesizeSpeech` :256, `synthesizeSpeechChunks` :308) and
  `frontend\src\components\Desktop\lib\api.ts`. Duplicate-code hazard.
- **`start-openjarvis.ps1` STARTS ONLY THE BACKEND** (line 57, uvicorn 8010).
  The desktop app launches separately, from the shortcut.
- **A REBUILD IS NOT AN INSTALL.** `npx tauri build` writes
  `frontend\src-tauri\target\release\`; the shortcut runs
  `%LOCALAPPDATA%\OpenJarvis\`. Reinstall with
  `target\release\bundle\nsis\OpenJarvis_0.1.0_x64-setup.exe /S`.
  ALWAYS SAY WHICH EXE A TEST RAN.
- **BUILD:** `npx tauri build` from `frontend\`, ~200 s, exits 1 on the
  signing warning - that is SUCCESS.
- **`backend.log` IS HELD OPEN.** `[IO.File]::ReadLines` FAILS. Use
  `Select-String`. It was at 3.99 MB against a ~4.19 MB roll on 09/18 - a
  NEGATIVE line delta means rotation, not a missing write.
