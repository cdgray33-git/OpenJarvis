## HARD FACTS A NEW WINDOW WILL GET WRONG

- **UVICORN'S ACCESS LOG DOES NOT RECORD PAGE OR ASSET FETCHES.** `GET /` returns 200
  and writes NOTHING to `backend.log`. API routes do log. Four greps for `GET /` came
  back empty against a working server and were nearly read as "the page was never
  opened." **Do not use backend.log to decide whether the frontend loaded.** `ws-accept`
  IS a real instrument and does land.
- **THE EXE EMBEDS THE FRONTEND. RESTARTING IT DOES NOT PICK UP A VITE BUILD.**
  `tauri.conf.json:7` `frontendDist` is `../../src/openjarvis/server/static`, embedded at
  `tauri build` time. `npm run build` rewrites that folder but cannot reach inside an
  already-built binary. Frontend change means FULL `npm run tauri build` then relaunch.
- **`npm run tauri build` EXITS 1 ON A SUCCESSFUL BUILD.** The exe and both bundles are
  produced, then the updater-signing step fails for want of `TAURI_SIGNING_PRIVATE_KEY`
  (`tauri.conf.json:35` `createUpdaterArtifacts: true`, pubkey at `:64`, no private key).
  Updater plugin is `active: false`. **Check the exe timestamp, not the exit code.**
  Build takes about 2m 40s on the Rust step.
- **THE BACKEND DOES SERVE THE FRONTEND** at `http://127.0.0.1:8010/`, 200, 849 bytes,
  from the same static dir. Useful as a patched-code check WITHOUT rebuilding the exe.
- **POST BODY IS `confirm_id` + `decision` ONLY** (`agent_manager_routes.py:2059-2060`).
  `turn_id` is NOT sent - it comes back in the RESPONSE from the registry (`:2100`).
  `decision` must be lowercase `approve` or `deny` (`:2062-2067`), else 400 before the
  registry is touched. Write-once: second POST gives 409 with the held decision. 404
  means expired, checked before `resolve()` (`:2085`). TIMEOUT is never client-settable.
- **CONFIRM FRAME SHAPES, READ LIVE FROM `tools\_stubs.py` 09/12.** request (`:365-373`):

  SERVER-AUTHORED (`:352-355`) - the UI renders it verbatim.
- **THE REQUEST FRAME IS PUBLISHED BEFORE THE EXECUTOR BLOCKS** (`:362-374`, callback
  `:377`), so the full window is available to answer. The RESOLVED frame fires on EVERY
  outcome including TIMEOUT (`:382-384`), so dismiss-on-resolved needs no local timer.
