## WHAT THE PATCH DOES

In `_stream_managed_agent`, after the MCP merge, `_allowed_tool_names` is built
from `stream_kwargs["tools"]` - the exact spec set handed to the model, config
tools plus discovered MCP tools - and logged at INFO. In the site 2 tool loop,
the first statement inside the `try:` refuses any `tool_name` not in that set,
BEFORE `ToolRegistry.get()`, with a `TOOLKIT REFUSAL` warning and a
`PermissionError`. The existing handler turns that into a normal failed tool
result, so the model sees the refusal and the UI gets `tool_call_end` with
`success=false`.

**CORRECTION TO THE W53 BRIEF.** W53 said to bind against the `seen` set built by
`_resolve_tool_specs()`. `seen` is LOCAL to that function and is never returned -
it is not reachable from `_stream_managed_agent`. Binding against
`stream_kwargs["tools"]` is the correct and strictly wider fix: it also covers
MCP tools, which `resolved_tools` does not.

**FAILS CLOSED BY DESIGN.** No configured tools and no MCP tools means an empty
set and every tool_call refused. The model was handed no tools in that case, so
any tool_call is unsolicited. Intended, not a bug.
